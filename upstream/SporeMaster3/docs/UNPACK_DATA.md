# Экспериментальная распаковка в `Data`

Документ описывает экспериментальный режим **полной распаковки архива в игровой вид** (`Data`),
который максимально приближает результат к тому, как данные лежат в самой игре.

## 1. Зачем

Обычный `unpack` раскладывает ресурсы как `group/name.ext` (папка = группа, имя = инстанс).
Это удобно, но не совпадает с настоящей структурой игры. Экспериментальный режим использует
**карту ключей игры** (`KeyMap.txt`), чтобы восстановить **реальный путь** каждого ресурса
(например `Arenas\Editors\ce_editor_background_sporepedia.gmsh`).

Это нужно, чтобы:
- понимать устройство данных по файлам (какие каталоги/имена реальны);
- готовить почву для полноценной распаковки/упаковки «как в игре»;
- сверять наши имена с игровыми.

## 2. Как работает

```powershell
dotnet run --project src/SporeMaster.Cli -- unpackdata <package> <output-dir> --keymap <KeyMap.txt>
```

Для каждого ресурса:
1. ключ `(type, group, instance)` ищется в `KeyMap`;
2. если найден — используется **точный реальный путь** из карты;
3. если нет — фолбэк на `group/name.ext`.

Ресурсы пишутся **как есть (байты)**, без конвертаций — так они и лежат в распакованном `Data`.

## 3. Проверенный результат

На `Spore_Game.package` (11676 ресурсов) с картой ключей `SporeBeta2008/Data/KeyMap.txt`:

| Источник имени | Ресурсов |
|----------------|---------:|
| из карты ключей | **6793** |
| фолбэк `group/name.ext` | 4883 |

То есть даже между **бета-** и релизной версиями общие хеши позволяют восстановить реальные имена
для ~58 % ресурсов. Получившаяся структура — настоящие игровые каталоги:
`AbilityTemplates`, `achievements~`, `adventure~`, `animations~` и т.д.

## 4. Связь с `DDFList`

В распакованном `Data` каталоги, входящие в сборку, описаны в файлах `*_DDFList.txt`
(`#include` других списков). Они определяют, что видит игра/редактор в «unpacked» режиме и что
попадает в сборку. См. `refs/SporeUnpackedData/SporeHeroWiiPCLeftOvers/Data/README.txt`.

**Реализовано:** `SporeMaster.Core/Names/DdfList.cs` разбирает список (строки-каталоги, `//`
комментарии, `#include` относительно включающего файла) и умеет проверять, лежит ли реальный путь
ресурса внутри перечисленных каталогов. В `unpackdata` опция `--ddflist <файл>` (вместе с
`--keymap`) распаковывает **только** ресурсы из перечисленных папок сборки:

```powershell
dotnet run --project src/SporeMaster.Cli -- unpackdata <package> <out> \
    --keymap KeyMap.txt --ddflist Spore_DDFList.txt
```

**Проверено:** `Spore_DDFList.txt` даёт 733 каталога (10 `#include`); `Spore_Game.package`
сокращается до ресурсов сборки (6793 с реальными путями из карты ключей, остальные пропущены).

## 4.1. «Тип ресурса → расширение/папка» (наблюдение)

Распакованный `Data` (leftovers 2008-беты и Wii Spore Hero) — **авторитетный** источник
соответствия типа ресурса расширению и папке. Например, тип **`trigger` (`0x024a0e52`) хранит
обычный текст** (`Config\*.txt`, `Cinematics\*.txt`, `scripts*\*.txt`); ресурс
`animations~/OptionProperties.trigger` совпадает по содержанию с `Config/OptionProperties.txt`.

Из `KeyMap` выводится таблица «type → расширение», например:

| Тип | Расширение | Примечание |
|-----|-----------|-----------|
| `0x2f7d0004` | `.png` | готовый PNG |
| `0x2f4e681b` | `.rw4`/`.rdx9` | RenderWare 4 |
| `0x2f4e681c` | `.raster` | текстура |
| `0x00b1b104` | `.prop` | свойства |
| `0xee17c6ad` | `.animation` | анимация |
| `0x024a0e52` | `.txt` | `trigger` — текст |
| `0x0472329b` | `.txt` | `arth`/`htra` — текст |

Это применяется, чтобы (1) давать корректное расширение при распаковке, (2) улучшать имена в
основном списке, (3) помечать текстовые типы как текст.

**Реализовано:** `keymap … --extensions ext.txt` выгружает таблицу «тип → расширение», а
`unpackdata` при отсутствии точного пути берёт расширение из карты (например, для типа
`trigger` — `.txt`), а не имя типа. Так `AppProperties.trigger` становится `AppProperties.txt`.

## 4.2. Реальная (lossless) перепаковка: raw ⇄ pack

Отдельно от экспериментальной раскладки есть **имя-независимая lossless перепаковка**:
`unpack --raw` раскладывает ресурсы по **числовому ключу**:

```
_raw/{type:X8}/{group:X8}/{instance:X8}.bin
```

`pack` распознаёт этот layout (`SporeMaster.Core/Dbpf/RawKeyPath.cs`) и собирает ключи напрямую из
пути, не обращаясь к реестру имён. Цикл:

```powershell
spore unpack <package> <dir> --raw
spore pack   <dir> <repack.package> --compress
spore diff   <package> <repack.package>      # -> "Archives are identical"
```

**Проверено:** `unpack --raw → pack → diff` даёт **идентичный** результат (по ключам и содержимому):
`BP2_Data.package` — 184/184, `CSA_Graphics.package` — 5822/5822, **`Spore_Game.package` — 11676/11676,
`CSA_Main.package` — 8431/8431**. Это эмпирическая проверка пути записи архива (идея заказчика №3 —
«проверка репака»).

## 5. Ограничения (эксперимент)

- Фолбэк для неизвестных ключей даёт `group/name.ext`, а не реальный путь.
- Локали/инстансы могут требовать особого обращения (`!`-имена в карте ключей).
- Итоговый каталог пока пишется напрямую в `<output-dir>` (без подпапки `Data`); при интеграции
  с тест-контуром игры подпапка будет добавлена.

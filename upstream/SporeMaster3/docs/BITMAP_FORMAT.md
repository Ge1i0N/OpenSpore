# Формат bitmap и PNG — рабочие заметки

Документ описывает «сырые» растровые ресурсы Spore (типы `bitImage`, `8bitImage`, `32bitImage`,
`48bitImage`) и их обмен с PNG. Так как PNG в .NET не входит в базовую библиотеку, кодеки PNG
написаны нами поверх штатного zlib (`ZLibStream`), без сторонних пакетов.

## 1. Типы bitmap-ресурсов

Из `reg_type.txt`:

| Имя | ID | Бит на пиксель | Каналов |
|-----|----|:--------------:|:-------:|
| `bitImage` | `0x03E421E9` | 1 | 0 |
| `8bitImage` | `0x03E421EC` | 8 (серый) | 1 |
| `16bitImage` | `0x03E421F0` | 16 | — (не поддержано) |
| `32bitImage` | `0x03E421ED` | 32 (BGRA) | 2 |
| `48bitImage` | `0x03E421EF` | 48 (RGB, по 16 бит) | 3 |

## 2. Бинарный формат

Числа заголовка — **BIG-endian** (проверено на реальных данных: `00 00 00 40` = 64).

```
int32  version      // 0
int32  width
int32  height
int32  channelCount // 0 / 1 / 2 / 3 — согласовано с типом
int32  bufferSize
byte[bufferSize] data
int32  unknown      // ТОЛЬКО для типа bitImage (1-bit)
```

`channelCount` — информационное поле, реальный формат данных определяется типом ресурса
(расширением/типом из архива).

### Раскладка данных (data)

- **bitImage (1 бит)**: строки по `width/8` байт; бит `k` (младший — пиксель `x+k`). 0 — чёрный,
  1 — белый. Ширина и высота должны быть кратны 8. Есть хвостовое поле `unknown` (обычно
  `width/8`).
- **8bitImage**: `width*height` байт серого.
- **32bitImage**: `width*height*4` байт, порядок на пиксель — **B, G, R, A**.
- **48bitImage**: `width*height*6` байт, по 3 little-endian `uint16` (R, G, B).

## 3. PNG-кодек

Реализован поверх `System.IO.Compression.ZLibStream`:

- **Кодирование**: 8-битный RGBA (color type 6), фильтр строк 0, чанки `IHDR`/`IDAT`/`IEND` с
  корректными CRC-32.
- **Декодирование**: color types 0 (серый), 2 (RGB), 3 (палитра), 4 (серый+альфа), 6 (RGBA);
  битовые глубины 1/2/4/8/16; прозрачность `tRNS`; фильтры строк 0–4 (None/Sub/Up/Average/Paeth).
  Чересстрочная развёртка (Adam7) **не** поддерживается (не встречается в нужных сценариях).

## 4. Конвертация

- **bitmap → PNG**: прочитать заголовок и данные → развернуть пиксели в RGBA8 → записать PNG.
- **PNG → bitmap**: прочитать PNG → RGBA8 → тип определяется по расширению (например
  `<имя>.32bitImage.png`) → упаковать данные.

Для 1- и 8-битных типов используется красный канал; для 48-битного — масштабирование 8→16 бит
(`v * 257`), что обратимо для 8-битных источников (round-trip байт-точный).

## 5. Соглашение об именах

При распаковке: `<instance>.<type>.png` (например `foo.32bitImage.png`). При упаковке файл
`*.png` читается как PNG, а тип берётся из части имени перед `.png`.

## 6. Проверка

Bitmap-ресурсы **есть** в реальных архивах: в `refs/_PackageFilesFinalVer/CSA_Graphics.package`
16 ресурсов типа `32bitImage` (например `animations~/cell_LO_colors.32bitImage`, 64×64).
Тесты декодируют их и проверяют правдоподобность размеров. Дополнительно формат проверяется
синтетическими тестами: PNG encode/decode (разные color types и фильтры), round-trip для всех
четырёх типов bitmap, и сквозной цикл pack → unpack → PNG.

Открытие (баг, найденный GUI): заголовок bitmap — **big-endian** (а не little-endian); ошибка
была исправлена именно благодаря превью в GUI и проверке на реальных ресурсах.

# Формат `.anim` (SPAnimation)

Анимация Spore (тип ресурса `animation` = `0xEE17C6AD`). Файл — **указательный** (pointer-based):
поля заголовка лежат по фиксированным смещениям, а таблицы каналов/событий задаются ссылками
(абсолютные смещения от начала файла).

## 1. Заголовок

| Смещение | Тип | Поле |
|---------:|-----|------|
| `0x00` | uint32 | магия `0x4D494E41` (`"ANIM"` — байты `41 4E 49 4D`) |
| `0x04` | uint32 | размер файла |
| `0x08` | int32 | версия (поддерживаются `0x14`..`0x19`, т.е. 20..25) |
| `0x0C` | char[0x100] | путь (ASCII, до 256 символов, добит нулями) |
| `0x10C` | int32 | 0 |
| `0x110` | int32 | id (FNV-хеш имени анимации) |
| `0x114` | 8 байт | резерв |
| `0x11C` | int32 | `0x3D088889` (≈ 1/30, длина кадра) |
| `0x120` | float | **длительность** (секунды) |
| `0x13C` | int32 | число событий |
| `0x140` | uint32 | указатель на таблицу событий |
| `0x144` | int32 | число каналов |
| `0x148` | uint32 | указатель на таблицу указателей каналов |
| `0x14C` | int32 | число «end pointers» |
| `0x150` | uint32 | указатель на массив указателей (в конце файла) |
| `0x154` | — | предикат ветвления (`branchPredicate`) |

## 2. Каналы

По указателю из `0x148` лежит массив `uint32[channelCount]` — указатели на каналы. Канал:

| Смещение | Тип | Поле |
|---------:|-----|------|
| `0x00` | uint32 | магия `0x4E414843` (`"CHAN"`) |
| `0x04` | uint32 | указатель на Animation* (может быть 0) |
| `0x08` | char[] | **имя канала** (ASCII, CString; обычно имя кости) |
| `0x88` | int32 | `movementFlags` |
| `0x8C` | int32 | флаги основного контекста (`primaryContext`) |
| `0x90` | char[4] | capability основного контекста |
| `0x9C` | int32 | флаги вторичного контекста |
| `0xA0` | char[4] | capability вторичного контекста |
| `0xAC` | int32 | `bindFlags` |
| `0xD4` | int32 | **число ключевых кадров** |
| `0xD8` | uint32 | указатель на ключевые кадры |
| `0xDC` | int32 | **число компонент** |
| `0xE0` | uint32 | указатель на метаданные компонент (по 32 байта) |

Компоненты (позиция/поворот/инфо/rigblock) описывают, как уложены кадры. **Реализовано чтение
компонент и их ключевых кадров** — см. раздел 4а. Ссылки на ключевые кадры/интерполяторы: полностью
(включая интерполяторы) — в планах.

### Дескриптор компоненты (32 байта)

Массив по указателю `0xE0` (`componentCount` = поле `0xDC`); запись:

| Смещение | Тип | Поле |
|---------:|-----|------|
| `0x00` | int32 | `flags` (младший ниббл — **тип**: 0 info, 1 position, 2 rotation, 3 rigblock) |
| `0x04` | int32 | `id` (заголовок компоненты: `POS`/`ROT`/`INFO`/…) |
| `0x08` | int32 | `keyframeOffset` (относительно указателя на кадры `0xD8`) |
| `0x0C` | int32 | `keyframeStride` (шаг между кадрами) |
| `0x10` | int32 | `index` |

Ключевые кадры: для `j`-го кадра позиция = `keyframePtr + stride*j + offset`. Значения (первая
часть кадра):

| Тип | Значения |
|-----|----------|
| 1 position | x, y, z, weight |
| 2 rotation | x, y, z, w, weight |
| 3 rigblock | value, weight |
| 0 info | time (int) + eventStartIndex + flags |

**Проверено:** на реальных анимациях (например `csa_sit_stop`) каждая кость имеет 9 компонент
(`Info, Position, Rotation, Rigblock×6`); декодируется 594 ключевых кадра и **1122** интерполятора,
значения конечны.

### Интерполяторы

За значениями кадра идут **интерполяторы** (запись 16 байт):

| Смещение | Тип | Поле |
|---------:|-----|------|
| `0x00` | float | `nextFactor` |
| `0x04` | float | `previousFactor` |
| `0x08` | byte | `nextMode` (0 default, 2 factor, 3 none) |
| `0x09` | byte | `previousMode` |
| `0x0A` | 6 байт | резерв |

Число интерполяторов на кадр: **position** — 4 (x, y, z, weight), **rigblock** — 2,
**rotation** — 1 (scale-интерполятор по смещению `+0x54` кадра). Размеры кадра: info `0x10`,
position `0x50`, rotation `0x64`, rigblock `0x28`.

## 3. События

По указателю из `0x140` лежит массив записей по `0x60` байт. Поля записи:

| Смещение | Тип | Поле |
|---------:|-----|------|
| `0x00` | int32 | flags |
| `0x04` | 4×12 | 4 селектора (flags, selectFlags, capability[4]) |
| `0x34` | int32 | archetype |
| `0x38` | int32 | eventGroup |
| `0x3C` | int32 | id |
| `0x40` | uint32 | указатель на **имя** события (только если `id != 0`) |
| `0x44` | int32 | parameter0 |
| `0x48` | float | maxSqrDist |
| `0x4C` | int32 | parameter1 |
| `0x50` | — | предикат |

## 4. Реализация

- `SporeMaster.Core/Anim/SpAnimation.cs` — чтение заголовка, событий (имена), каналов
  (имя, флаги, число кадров/компонент), **компонент с ключевыми кадрами** (типы
  info/position/rotation/rigblock) и **интерполяторов** кадров.
- `SporeMaster.Core/Anim/SpAnimationTextWriter.cs` — **текстовый дамп** (`version/id/length`,
  события, каналы, компоненты, кадры, интерполяторы).
- CLI: `anim <файл.anim> [--channels] [--limit N]`; `anim <in.anim> <out.anim_t>` — дамп в текст.
- Превью в GUI: сводка по анимации (каналы, компоненты, ключевые кадры).
- Тесты: синтетический файл (заголовок, канал, событие), отказ по магии, разбор 300 реальных
  анимаций (версии 21 и 25) с проверкой декодированных кадров, текстовый дамп.

**Проверено:** все 2436 анимаций в тестовых архивах читаются (магия совпадает, версии 21 и 25);
например `animations~/csa_sit_stop.animation` — 9 каналов (`root`, `head`, `R foot`, `L foot`,
`eyes`, `MouthMorphs`, `R grasper`, `L grasper`, …) по 9 компонент, 594 ключевых кадра.

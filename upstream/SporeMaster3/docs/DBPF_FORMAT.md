# Формат .package (DBPF) — рабочие заметки

Документ фиксирует понимание формата, на которое опирается код. Все многобайтовые числа —
**little-endian**. Проверено на реальных архивах Spore (бета 2.0 и релиз 3.0).

## 1. Сигнатуры

| Сигнатура | Значение | 4 байта |
|-----------|----------|---------|
| `DBPF` | обычный архив | `44 42 50 46` |
| `DBBF` | большой архив (64-битные смещения) | `44 42 42 46` |
| `DBPP` | защищённый контейнер | `44 42 50 50` |

## 2. Заголовок DBPF (96 байт)

| Смещение | Размер | Поле | Примечание |
|---------:|-------:|------|-----------|
| 0x00 | 4 | Magic `DBPF` | |
| 0x04 | 4 | Major | 2 (бета) или 3 (релиз) |
| 0x08 | 4 | Minor | 0 |
| 0x0C | 20 | резерв | нули |
| 0x20 | 4 | IndexMajor | обычно 0 |
| 0x24 | 4 | IndexCount | число записей |
| 0x28 | 4 | — | 0 |
| 0x2C | 4 | IndexSize | размер блока индекса |
| 0x30 | 12 | резерв | нули |
| 0x3C | 4 | IndexMinor | 3 (в легаси-коде ошибочно называлось «Always3») |
| 0x40 | 4 | IndexOffset | абсолютное смещение индекса |
| 0x44 | 28 | резерв | нули |

Заголовок **одинаков** для DBPF 2.0 и 3.0; различаются только числа версии. Именно поэтому
чтение бета-архивов не требует отдельной ветки — достаточно универсального парсера индекса.

## 3. Заголовок DBBF (120 байт)

Отличие от DBPF — 64-битные поля размера и смещения индекса:

| Смещение | Размер | Поле |
|---------:|-------:|------|
| 0x28 | 8 | IndexSize |
| 0x34 | 4 | IndexMinor |
| 0x38 | 8 | IndexOffset |

## 4. Блок индекса

Начинается со **IndexType** (4 байта) — битовой маски:

| Бит | Значение |
|----:|----------|
| 0 | поле **type** одинаково для всех записей |
| 1 | поле **group** одинаково для всех записей |
| 2 | поле **unknown** одинаково для всех записей |

Сразу за маской идут значения «общих» полей (по одному на установленный бит), затем записи.

Каждая запись содержит (в порядке следования):

| Поле | Размер | Читается |
|------|-------:|----------|
| type | 4 | если бит 0 не установлен |
| group | 4 | если бит 1 не установлен |
| unknown | 4 | если бит 2 не установлен |
| instance | 4 | всегда |
| offset | 4 (8 для DBBF) | всегда |
| packedSize | 4 | всегда; старший бит маскируется |
| memSize | 4 | всегда |
| compression | 2 | `0xFFFF` = RefPack, `0` = без сжатия |
| flags | 2 | обычно `1` («saved») |

### Наблюдения по реальным архивам

| Архив | Версия | IndexType | Записей |
|-------|:------:|:---------:|--------:|
| `_PackageFilesBetaVer/CellGame.package` | 2.0 | `0x06` | 442 |
| `_PackageFilesFinalVer/Spore_Game.package` | 3.0 | `0x04` | 11676 |

- `0x06` (биты 1 и 2): общие `group` и `unknown`; `type` и `instance` — по-элементно.
- `0x04` (бит 2): общий `unknown`; `type`, `group`, `instance` — по-элементно.

## 5. Данные и сжатие

Данные записей лежат по `offset` и занимают `packedSize` байт (при сжатии) или `memSize` (без).
При `compression == 0xFFFF` применяется RefPack.

### Поток RefPack

```
10 FB  <размер: 3 байта LE>  <команды...>
```

Команды декодируются по значению управляющего байта:

- `0xFC..0xFF` — «хвост»: 0..3 байта литералов, конец потока;
- `0xE0..0xFB` — блок литералов, длина `((c & 0x1F) << 2) + 4`;
- `0xC0..0xDF` — 4-байтная форма (литералы + копия со смещением);
- `0x80..0xBF` — 3-байтная форма;
- `0x00..0x7F` — 2-байтная форма.

Копирование допускает перекрытие (семантика RLE), поэтому при `copySize > copyOffset`
копируем побайтно.

## 6. Сопоставление с именами

Имена восстанавливаются по реестрам:

- `reg_type.txt` — тип (расширение) ↔ ID типа;
- `reg_file.txt` — имя группы/инстанса ↔ ID;
- `reg_property.txt`, `reg_simulator.txt` — свойства и атрибуты симулятора.

Строка реестра вида `имя` (без хеша) означает `ID = FNV(имя)`; строка `имя<TAB>0x…` задаёт ID
явно (псевдонимы, в т.ч. с `~`). Относительный путь ресурса: `group/name.ext`.
